# نقش‌نگار — ارتقای یکپارچه وب و اندروید

شاخه اجرا: `feat/complete-platform-upgrade-2026-11-26`

## تصمیم‌های محصول
- هویت نقش‌نگار، نام، لوگو، طراح بلوک و جریان‌های فعلی حفظ می‌شوند.
- وب و Android از یک کدبیس React/Vite + Capacitor استفاده می‌کنند.
- موسیقی پیش‌فرض را مدیر انتخاب می‌کند؛ کاربر فقط کنترل‌های پخش، توقف، صدا، موقعیت و جابه‌جایی در کتابخانه مجاز را دارد.
- موسیقی فقط در حالت فعال/قابل مشاهده بودن برنامه پخش می‌شود. با visibilitychange، pagehide یا blur متوقف می‌شود؛ autoplay بدون تعامل کاربر اجباری نیست.
- فایل موسیقی در bucket خصوصی qnr-music نگهداری می‌شود؛ فایل صوتی حداکثر ۵۰ MiB است.
- مجوز انتشار، صاحب حق و نوع مجوز برای هر آهنگ ثبت می‌شود.

## بخش‌های در دامنه
1. سیستم طراحی سراسری: رنگ‌ها، تایپوگرافی فارسی، RTL، کارت‌ها، سایه‌ها، پس‌زمینه‌های بافت‌دار، کنترل‌ها، dark mode و reduced motion.
2. پروفایل، گالری، فید، ریلز، تعاملات، دنبال‌کردن، ذخیره و گزارش.
3. پنل مدیریت: کتابخانه موسیقی، مدیریت محتوا و ابزارهای مدیریتی موجود؛ سپس کاربران، نقش‌ها، اعلان‌ها، تنظیمات و عملیات فروشگاه.
4. موسیقی: آپلود مدیریتی، متادیتا و کاور، انتخاب آهنگ پیش‌فرض، پخش‌کننده مشترک وب/Android و توقف در پس‌زمینه.
5. آزمون: typecheck/build، آزمون migration/RLS، آزمون مسیرهای وب، Capacitor sync و APK Debug.

## مرزهای ایمنی
- این شاخه migration و کد پیشنهادی را نگه می‌دارد؛ تا زمان بازبینی و تأیید جداگانه، migration روی دیتابیس production اجرا نمی‌شود.
- هیچ service-role key یا secret در کلاینت یا APK قرار نمی‌گیرد.
- دسترسی مدیر با qnr_private.qnr_is_admin() در RLS بررسی می‌شود؛ پنهان‌کردن UI مجوز ایجاد نمی‌کند.
- Storage خصوصی می‌ماند و پخش با signed URL کوتاه‌عمر انجام می‌شود.
- حقوق موسیقی باید توسط بارگذار تأیید شود. فایل دارای مجوز نیازمند URL معتبر است.

## محدودیت‌های انتشار
- background audio عمداً پیاده‌سازی نمی‌شود.
- پخش خودکار مرورگر ممکن است تا تعامل کاربر مسدود شود.
- این سند به‌تنهایی اثبات‌کننده تکمیل ویژگی‌ها نیست؛ وضعیت نهایی باید بر اساس CI و آزمون واقعی ثبت شود.
